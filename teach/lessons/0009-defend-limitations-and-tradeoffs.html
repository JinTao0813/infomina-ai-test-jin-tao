Metric and analysis weaknesses

  1. 20-event threshold: pragmatic and not sensitivity-tested at 10, 30, or 50.
  2. Finite-sample bias: the plug-in entropy estimator tends to depend on observed history; no correction or stability curve is provided.
  3. Check-in-weighted cohorts: active users contribute more to pooled category shares; equal-user shares would answer a different question.
  4. Bootstrap scope: percentile intervals quantify eligible-sample resampling uncertainty, not representativeness or causality.
  5. Metric API edge cases: location/group role collisions lack a tailored validation error, and empty output columns use object dtype.
  6. Raw-file fingerprints: README records hashes, but notebook execution does not assert them before loading.

Prototype weaknesses

  1. Hand-designed weights: 70/30 blending, the 0.50 sparse threshold, weekend adjustment, and power curve are inspectable choices—not estimated optima.
  2. Synthetic confidence: confidence values are fixed demo inputs; no production estimator or calibration exists.
  3. Popularity is not relevance: 0.35 + 0.60 × popularity is an illustrative baseline transform, not personalized utility.
  4. Historical candidates: support only proves occurrence in the old sample, not continued existence, quality, openness, safety, or suitability.
  5. Category familiarity is coarse: binary presence ignores frequency, recency, taxonomy drift, and current intent.
  6. No effectiveness evidence: deterministic reranking and UI tests establish behavior, not user benefit.
  7. Operational gaps: no CI, deployment, monitoring, auth, persistence, live venue feed, retention enforcement, or privacy review.

Tradeoffs worth defending

  • Data-derived pseudonyms over invented names: less delightful, but more honest because the source has no venue names.
  • Static analysis artifact: extra export machinery, but reviewers can read results without raw data or FastAPI and stale content fails the build.
  • Direct browser-to-FastAPI calls: simple for a local prototype, but a production deployment would likely use a same-origin gateway and stronger operational controls.
  • Deterministic ranker over a trained model: no effectiveness claim, but every behavior is inspectable and easy to test within interview scope.

“The largest uncertainty is still measurement validity: voluntary check-ins and history length constrain what entropy means. The prototype adds another layer of illustrative assumptions—confidence, weights, and a popularity-based baseline. I made those assumptions transparent and deterministic, but I would first test entropy stability and threshold sensitivity, then use current consented data and a powered experiment before tuning or operationalizing the ranker.”

Retrieve

Which prototype parameter is learned from outcomes?
None. Profiles, confidence values, blend weights, threshold, popularity transform, and curve are deterministic illustrative choices.
Why choose validity work before a better model?
A more sophisticated model cannot repair a selected observation process or an unstable target; first establish that the signal is measured reliably enough to justify use.

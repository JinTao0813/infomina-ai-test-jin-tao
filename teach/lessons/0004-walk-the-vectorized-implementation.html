Output: group keys plus observation_count, unique_location_count, entropy, and normalized_entropy. Base 2 is fixed. Rows are observations; there is no weight argument.

The five-stage trace

1Validate contractNormalize the group-column argument; reject an empty/duplicate group list, missing columns, null group keys, and null locations.
2Count locationsGroup by group keys + location. Each result row is one observed location with its event count.
3Make probabilitiesWithin each group, transform location counts to their sum; divide each location count by that group total.
4Aggregate entropyCompute −p·log₂(p) per group-location row, then aggregate counts, support size, and entropy by group.
5NormalizeDivide by log₂(K) when K > 1; define zero otherwise; clip tiny floating noise to [0,1].

Why the group-location table is essential

Entropy is a property of the distribution over locations, not individual rows. Repeated check-ins at the same venue must become one count before probabilities are calculated. The second aggregation then turns those location-level components into one output row per user.

Defensive pandas choices

  • observed=True avoids materializing unobserved categorical combinations.
  • sort=False avoids unnecessary sorting and preserves encounter order.
  • dropna=False makes grouping semantics explicit after null keys have already been rejected.
  • transform("sum") aligns each group total back to every group-location row without a manual Python loop or merge.

Complexity and boundaries

The main work is grouped aggregation over N events, with memory also influenced by the number of distinct group-location pairs. pandas is reasonable for this roughly 800k-row analysis. Larger pipelines could use partitioned Parquet plus Polars or Spark while preserving the same contract.

Actual improvement candidates: reject a location column that duplicates a group role with a tailored message; return stable documented dtypes for empty input instead of all-object columns; and consider whether clipping should use an explicit floating tolerance. Configurable weights and log bases are not current features.

Why aggregate by group + location first?
All events at the same location must become one probability mass before entropy is calculated; otherwise the distribution is represented incorrectly.
What exactly are the API inputs and outputs?
Inputs are a DataFrame, one or more group columns, and one location column. Outputs are group keys, observation count, unique-location count, raw base-2 entropy, and normalized entropy.
